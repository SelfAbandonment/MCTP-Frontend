## 五、待确认需求（需服主 / 评审决定）

> 以下两项是当前实现里「需要对方拍板」的点，确认前不做进一步改动。

### 1. 健康接口补充真实在线人数 / TPS 字段（后端）

- **现状**：`StatusBarSection.vue` 已接 `GET /api/v1/health/` 做 10 秒轮询，但该接口目前只返回 `status` / `version`，没有在线人数与 TPS，故这两项回退展示模拟值。
- **需求**：后端在 `GET /api/v1/health/` 响应中补充字段，前端无需改动即可自动切换真实值（已兼容多种命名）：
  - `online`（整数，当前在线玩家数；也兼容 `players_online` / `online_players` / `players`）
  - `tps`（浮点数，0–20；也兼容 `server_tps`）
- **验收**：接口返回上述字段后，状态条右上角标签由「服务正常 · 数值模拟」变为「实时数据」。
- **原因**：TPS / 在线人数是审核方判断「真实性」的关键指标。

### 2. 是否抽离基础组件 `SectionCard` / `SectionTitle`（前端重构）

- **现状**：9 个功能区块各自维护 `.preview-card` / `.preview-section-title` 的样式与结构，存在重复。
- **待定**：是否进行「组件瘦身」——抽出 `SectionCard.vue`（卡片容器）与 `SectionTitle.vue`（区块标题），统一视觉，后续改风格只动一处。
- **取舍**：收益是长期维护性更好；成本是一次涉及多组件的重构（有回归风险）。
- **结论待服主 / 评审确认后再排期**，确认前保持现状不动。
